# 0026. Bind combined acceptance to checked contributor origins

- Status: Proposed
- Date: 2026-10-17

## Context

Two edits can pass their own tests and fail when combined. Identical candidate bytes can also come from different attempts with different permissions. ADR 0008 requires a serialized integrator and combined check for two slices. I need evidence that retains both contributors and every checked transition to the final result.

## Decision

I propose one frozen parent with exactly two child tasks from the same committed base. Each child owns one distinct existing text file in independent scratch. The parent reserves seven dispatches for the baseline, two writers, two replay checks, full final check and one review, plus an explicit private integration minute allowance within the parent limit. Omitting the allowance keeps the original one minute; existing preparations retain their frozen value. Earlier planning remains charged, and child task limits stay additional gates.

I replay the exact substantive deltas in order. Each cumulative candidate must pass its declared checks before a compare-and-swap advances a private integration ref. The origin binds source, policy, criteria, both writer attempts and candidates, check definitions and results, and the exact old/new tree chain. Intermediate integration touches no source branch.

The final candidate needs its own full check and a separate native review of both contributors. Passing slices or replay checks cannot replace that barrier. Destination-specific acceptance revalidates the complete origin and evidence before creating one new branch. Child work cannot be accepted independently.

Pause closes parent admissions. Explicit Resume rechecks quiescence, phase proofs and remaining budget and launches nothing. Parent Stop requests cleanup for every owner. Missing closure leaves the group unknown; restart never resubmits work or infers historical process closure from an observed ref.

## Why

I chose a small fixed graph so the complete cost can be reserved before work starts. A shared directory would make writer provenance harder to prove. A summary of two successful slices would lose the exact integration chain.

Checked ref transitions cost extra tests and durable records. They let me refuse a final result whose bytes, contributor or evidence changed, even when an earlier stage passed. I accept a blocked group when ownership is uncertain.

## Consequences

- This proposal awaits my acceptance. Accepted ADRs 0008 and 0012 remain unchanged.
- The initial workflow supports two disjoint file replacements, Quick quality and one Keep it simple review under guided or balanced authority.
- Native review proves process independence only when the same family supplies writer and reviewer. It grants no model-diversity claim.
- Offline fixtures establish controller mechanics. Useful connected two-slice work, route qualification, ten real D2 tasks and user acceptance remain separate exits.
