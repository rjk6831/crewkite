# 0001. Build a coding workspace for my daily projects

- Status: Accepted
- Date: 2026-10-07, refined 2026-10-09

## Context

I write code every day on my own products with a local model and three coding subscriptions. Each tool has its own interface, limits and reset schedule. I switch between four or five windows and write handoff notes by hand when one runs low. One early draft of this design drifted toward a general workspace for research, documents and no-code app building.

## Decision

CrewKite is a coding workspace. It runs a configurable team of a lead or architect, an orchestrator, coding workers, reviewers, advisors and an optional overseer across local and subscription routes. Its first job is to become the interface I choose every day for my own repositories.

## Why

I know this workflow's friction firsthand, so I can judge the product honestly with real tasks. A general workspace would compete with every assistant on the market and prove nothing about the coordination problem I actually have.

## Consequences

- A feature earns its place by helping a coding task finish. Research, document and no-code journeys are out of scope.
- The value is a hypothesis. I test it by completed work and the manual coordination it removes, recorded per task.
- When I keep reaching for another tool, I fix the specific friction first.
