# Trying the preview

Thank you for trying CrewKite on a real project. This guide covers what to do once you have the normal candidate I supplied. Setup and packaging details live in the [distribution notes](distribution.md), and I do not repeat them here. Opening the app starts no model task.

## First steps

1. Open the supplied normal candidate. It starts without a synthetic project.
2. Choose Add project and select the exact Git repository root.
3. Choose New task and select that project.
4. Open Usage and capacity and review explicit provider setup before sending work. The [provider notes](providers.md) explain each path.

## Planning is separate from coding

Review the planning permission, then send a bounded objective. Answer questions, inspect the proposed criteria and scope, and choose Adopt plan yourself. Adoption saves the task contract and starts no coding work.

Afterward, prepare the source, grants and finite limits as a separate step. Review them, then choose Start.

Saving a material model or effort change creates a linked planning run. It also returns the task contract to provisional, so you need a fresh valid plan adopted before preparing execution. Make such changes during discussion, before execution. Once an execution run exists, it is retained and material planning changes are unavailable there. Ordinary messages are kept as guidance and do not replace the run.

## Reviewing the result

Inspect the retained work under Changes. Checks and review is a separate step that reports its own evidence. A matching result still needs your destination-specific approval before CrewKite creates one new local branch. Nothing merges, checks out, pushes or publishes, and your original checkout is not modified.

## Stop and reopening

Stop ends work you no longer want. Reopening the same home shows what is known and what is uncertain, and it launches nothing. If a command receipt is uncertain, it keeps its original retry identity, and I only offer retrying that exact command. Ownership that cannot be resolved is shown as such. It gives no permission to launch again and no claim that work finished. The [conversation CLI guide](../apps/cli/README.md#task-conversations) lists the controls, and [continuity](continuity.md) explains the restart rules.

## Local connection modes

Local setup defaults to a dedicated token. An explicit CLI configuration can instead choose no authentication, on this device's loopback address only. The desktop reports that saved mode. It has no selector in the main interface and never downgrades by itself. Model eligibility is separate from qualification, so an eligible loaded model is still unqualified. See the [Local models notes](providers.md#local-models) for the current limits.

## Usage and context labels

Usage and context figures appear as reported or last observed, with their source and time. Missing data stays unknown. CrewKite does not estimate current context fill, and it does not infer a quota from token counts.

- the concrete result you observed, and any refusal you saw
- the retained changes or evidence you found
- how Stop and reopening behaved
- whether the next action was clear at each point

That is enough. This preview is not a release, and your notes do not stand in for any acceptance decision.
